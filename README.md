# xsub

[English](README.en.md) · Новости: [t.me/xsuby](https://t.me/xsuby) · Чат: [t.me/xsuby_chat](https://t.me/xsuby_chat)

Подписки, списки доменов и сторож узлов для **XKeen + Xray** на роутерах Keenetic / Netcraze. Есть серверный режим (Docker, x86_64/arm64).

XKeen перехватывает трафик и запускает Xray. xsub управляет содержимым.

## Возможности

- **Подписки:** ссылки `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://` (`hy2://`), `wireguard://` (`wg://`), `socks://`, `http(s)://` (списком или в base64); форматы **Clash/mihomo YAML**, **sing-box JSON**, **JSON Xray** (как отдают Remnawave/Marzban). Транспорты TCP (в т. ч. с HTTP-заголовком), WebSocket, gRPC, HTTPUpgrade, XHTTP, mKCP; TLS и Reality; у Hysteria2 — salamander, привязка к сертификату, перебор портов. Фильтры по имени, несколько подписок. Если панель с лимитом устройств (Remnawave) без HWID отдаёт заглушки, запрос повторяется с постоянным `x-hwid` роутера — файл `/opt/etc/xsub/hwid` создаётся сам.
- Для подписки можно включить **«Всегда отправлять HWID»**: тогда идентификатор передаётся уже в первом запросе. По умолчанию настройка выключена, но автоматический повтор с HWID при ответе без подходящих узлов сохраняется. Провайдер может учитывать роутер в лимите устройств.
- **Балансировщик** `leastPing` + observatory; сборка в `07_xsub.json`.
- **Сторож** проверяет активный узел раз в минуту **реальной загрузкой** (32 КБ по умолчанию — больше порога блокировок, при которых `generate_204` проходит, а трафик обрывается). Свои адреса для проверки — в `watchdog.check_urls`. Переключение через API Xray, без перезапуска ядра.
- **Надёжность:** запасные узлы проверяются загрузкой в фоне раз в 30 минут; история за сутки; при сбое первыми идут проверенные узлы, а не самые быстрые по пингу.
- **Переход на быстрый узел:** если запасной надёжен не хуже текущего и быстрее его на `switch_faster_ms` (по умолчанию 200; 0 — выкл.), сторож переключится без отказа. Перед переходом оба узла перемеряются в один момент — общий шум канала и CPU не превращается в ложную разницу. Не чаще раза за цикл фоновых проверок.
- **Резервные узлы:** ссылкой или переносом из конфигов XKeen; также резерв через интерфейс роутера (`nwg0`, `ovpn_br0` — трафик идёт через туннель Keenetic OS, минуя Xray). При отказе всей подписки сторож переходит на резерв и раз в 10 минут пробует вернуться.
- **Группы:** свой список через подмножество узлов (по фильтру-регулярному выражению). У группы свой балансировщик и сторож.
- **Списки «Напрямую» и «Через VPN»** на странице, внешние списки по ссылке в любом популярном формате (plain, dnsmasq, surge/clash, egern, sing-box; обновляются ежесуточно). Перед применением конфиг проверяется `xray -test`; при ошибке ничего не меняется.
- **«Куда пойдёт этот сайт?»** — домен, ссылка или IP: правило, список и узел (включая категории `.dat`).
- **Самовосстановление:** подменённые `05_routing.json`/`07_xsub.json` возвращаются; пропавшее на 3 минуты ядро — перезапуск XKeen (mihomo не трогается).
- **Telegram-уведомления:** переключения, отказ/восстановление, конец подписки/трафика, самовосстановление, новые версии. При блокировке Telegram сообщения идут через VPN. Заголовок — имя роутера.
- **История** переключений и доступность за сутки по узлам и группам; бэкап всех настроек одним файлом; обновление кнопкой; интерфейс RU/EN.
- **Geo-файлы:** ежесуточное обновление [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) (`geosite_itdog.dat`).

Один статический бинарник без зависимостей, веб-интерфейс встроен.

## Требования

- Keenetic / Netcraze с Entware и [XKeen](https://github.com/jameszeroX/XKeen) с ядром **Xray** (`xkeen -xray`).
- Архитектура: aarch64, armv7, mipsel, mips. **Не меньше 100 МБ свободного места** — на практике USB-накопитель.
- Место: ядро Xray ~32 МБ, `geoip.dat` + `geosite.dat` ~6 МБ, xsub ~8 МБ, XKeen с зависимостями 3–5 МБ. Итого ≈50 МБ плюс запас под временные файлы opkg, кэш и журнал. Встроенного хранилища (обычно раздел 55 МБ) не хватит.
- Скорость упирается в процессор роутера (шифрование на CPU, ускорения нет): mips/mipsel — заметно ниже скорости канала, armv7 — середина, aarch64 — максимум из доступных.
- Трафик сторожа: проверка узла — 32 КБ; 30 узлов раз в 30 минут ≈ 45 МБ/сутки.

Архитектура роутера:

```sh
uname -m                  # aarch64, armv7l, mips…
opkg print-architecture   # у MIPS различает mipsel и mips
```

## Установка

По SSH на роутере (в Entware):

```sh
curl -fsSL https://raw.githubusercontent.com/furriest/xsub/main/install.sh | sh
```

Установщик определит архитектуру, проверит место, поставит пакет, создаст конфиг и покажет адрес страницы, логин и пароль. XKeen при необходимости предложит поставить сам (`XSUB_YES=1` — без вопросов). Пока подписка не добавлена, конфиги Xray не трогаются.

Репозиторий opkg для `opkg upgrade` (про VPN не знает — на заблокированном канале может не достучаться до GitHub):

```sh
curl -fsSL https://raw.githubusercontent.com/furriest/xsub/main/install.sh | XSUB_FEED=1 sh
```

Ручная установка (архитектура — своя, пакеты объявлены `Architecture: all`, opkg чужую сборку не отклонит):

```sh
case "$(uname -m)" in
  aarch64|arm64) A=aarch64 ;;
  armv*)         A=armv7 ;;
  mips*)         opkg print-architecture | grep -q mipsel && A=mipsel || A=mips ;;
esac
opkg install "https://github.com/furriest/xsub/releases/latest/download/xsub_$A.ipk"
```

Обновление: кнопка «Обновить» в настройках (скачивает через VPN, сверяет SHA256, журнал — `/tmp/xsub-update.log`) или повторный install.sh.

В Xray-конфигах вручную ничего не настраивается: `04_outbounds.json` можно оставить пустым, `05_routing.json` пишет xsub. Вкладка «Настройки» → «Окружение» показывает неполадки и команду для исправления. Опционально на стороне Keenetic/XKeen: шифрованный DNS (DoT/DoH), политика `xkeen` в «Приоритетах подключений», IPv6 (`xkeen -ipv6`), исключение российских IP (`xkeen -gips`/`xkeen -dgips` — адреса идут напрямую даже при наличии в «Через VPN»).

## Docker (сервер)

Тот же xsub в контейнере: ядро Xray, подписки, сторож; весь трафик встроенного SOCKS5-прокси идёт через рабочий узел.

```sh
curl -fsSL -o docker-compose.yml https://raw.githubusercontent.com/furriest/xsub/main/docker-compose.yml
docker compose up -d
```

Логин и пароль (`http://<сервер>:8099/`) печатаются в лог первого запуска: `docker compose logs`. Образ `ghcr.io/furriest/xsub` собирается из релизного тега; обновление: `docker compose pull && docker compose up -d` (или watchtower по метке в compose). Кнопка «Обновить» в контейнере скрыта.

Отличия серверного режима (включается по `/.dockerenv` или `XSUB_SERVER=1`):

- SOCKS5-вход собирает entrypoint при первом запуске из `SOCKS_PORT` (1080), `SOCKS_USER`, `SOCKS_PASSWORD` → `01_inbounds.json` в confdir. Без логина/пароля вход без авторизации — не выставляйте такой порт в интернет. Пересборка: удалить файл и перезапустить контейнер.
- Трафик вне списков направляется переключателем **«По умолчанию»** (вкладка «Списки и группы»): в серверном режиме — «Через VPN», на роутере — «Напрямую».
- Журнал — в stdout; история проверок — в volume `xsub-data`.
- Страница доступна только с частных адресов (LAN, SSH-туннель); снаружи — «Доступ из интернета» в настройках (пароль обязателен).
- Дефолты: `/usr/local/bin/xray`, confdir `/data/xray`, `xsub-xray-restart` вместо `xkeen -restart`.

Без Docker возьмите бинарник `xsub-<версия>-x86_64`: Xray ставится отдельно, пути и `restart_cmd` — в `config.json`, запуск с `XSUB_SERVER=1`.

## Что меняется в конфигах Xray

xsub пишет два файла в папку конфигов XKeen (`/opt/etc/xray/configs`):

| Файл | Содержимое |
|---|---|
| `05_routing.json` | правила из списков, правило для `force-proxy-*`, балансировщики |
| `07_xsub.json` | узлы, observatory, API (`127.0.0.1:10085`), локальные входы для проверок (`10990+` цели, `11000+` узлы) |

`05_routing.json` полностью принадлежит xsub — свои правила переносите в списки, а не в файл.

Исходники сохраняются в `/opt/etc/xsub/backup/original/`. Откат:

```sh
/opt/etc/init.d/S99xsub stop
xsub -restore
```

`opkg remove xsub` откатывает сам. Если в ваших файлах уже есть секции `api`/`observatory` или `routing` в файле после `05_routing.json`, xsub конфиг не применит и объяснит, что поправить.

## Списки

Одна запись на строку, комментарии через `#`:

```
example.com                    # домен со всеми поддоменами
=example.com                   # только этот домен
ext:geosite_itdog.dat:youtube  # категория из файла в папке geo-файлов
geosite:telegram               # категория из geosite.dat
1.2.3.0/24                     # IP или подсеть
regexp:^ads\.                  # регулярное выражение
https://…/list.txt             # внешний список
```

Порядок правил: «Напрямую» → группы (в порядке на странице) → «Через VPN». Вне списков — по переключателю **«По умолчанию»**.

Внешние списки скачиваются при сохранении и обновляются ежесуточно; на диск пишутся при изменениях. Формат определяется автоматически и разбирается целиком:

- голые домены и подсети, `=домен`, dnsmasq-строки (`server=/домен/…`);
- классические правила клиентов (surge, shadowrocket, loon, stash, quantumult-x, payload Clash): `DOMAIN`, `DOMAIN-SUFFIX`, `DOMAIN-KEYWORD`, `IP-CIDR`, `GEOIP` и варианты `HOST-*`; третье поле (`all`, `no-resolve`) игнорируется;
- типизированные YAML-блоки egern: `domain_set`, `domain_suffix_set`, `domain_keyword_set`, `domain_regex_set`, `ip_cidr_set`;
- JSON rule-set sing-box: `domain`, `domain_suffix`, `domain_keyword`, `domain_regex`, `ip_cidr`.

Записи без эквивалента в правилах Xray (process_name, порты, ASN) пропускаются. Пример: `https://raw.githubusercontent.com/VPSDance/ai-proxy-rules/main/rules/surge/all.list`.

Группы: название и фильтр узлов (регулярное выражение по имени, напр. `(?i)нидерланды|NL`). У группы появляется свой список; если подходящих узлов нет — трафик идёт основной целью.

## Настройки

Основное — на странице («Настройки»); сохраняется в `/opt/etc/xsub/settings.json` поверх `config.json`, xsub перезапускается сам. Остальное — в `config.json` (после правки: `/opt/etc/init.d/S99xsub restart`).

| Параметр | По умолчанию | Назначение |
|---|---|---|
| `listen` | `0.0.0.0:8099` | адрес страницы |
| `user`, `password` | `admin`, случайный | вход |
| `log_file`, `log_max_kb` | `/tmp/xsub.log`, `256` | журнал: `""` — только на странице; `/tmp` — оперативная память; на накопителе — пишет на флеш |
| `sub_interval_hours` | `6` | обновление подписок (после неудачи — 10 минут) |
| `user_agent` | `v2rayN/7.0` | формат ответа панели; у подписки можно задать свой |
| `max_nodes` | `60` | максимум узлов из подписки |
| `ui_allow_wan` | `false` | доступ из интернета. Соединение не шифровано — включайте только с надёжным паролем |
| `ui_allow_hosts` | — | допустимые имена в заголовке Host (защита от DNS rebinding) |
| `xray.restart_cmd` | `xkeen -restart` | перезапуск ядра |
| `xray.template_tag` | — | у какого outbound брать sockopt (метка) |
| `xray.manage_api` | `true` | `false`, если API Xray уже настроен вами (нужен `RoutingService` на `xray.api_listen`) |
| `xray.fallback_tag` | — | устарело: запасной outbound из конфигов XKeen; лучше перенести в «Резервные узлы» |
| `watchdog.interval_sec` | `60` | тик сторожа |
| `watchdog.fails_to_switch` | `2` | неудач подряд до переключения |
| `watchdog.test_url`, `test_bytes` | Cloudflare, `32768` | что и сколько качать для проверки (`{bytes}` подставляется) |
| `watchdog.check_urls` | — | адреса, которые тоже должны открываться через узел |
| `watchdog.latency_url` | `gstatic.com/generate_204` | замер задержки; если не открывается — меряется по `test_url` |
| `watchdog.switch_faster_ms` | `200` | переход на более быстрый узел при разнице ≥ N мс (0 — выкл.; ≤ раза за цикл; свежий замер обоих перед переходом) |
| `watchdog.background_cycle_min` | `30` | период фоновой проверки запасных узлов (0 — выкл.) |
| `watchdog.stats_file` | `/tmp/xsub-stats.json` | история проверок между перезапусками xsub |
| `watchdog.restart_delay_sec` | `7` | пауза после старта ядра перед закреплением узлов |
| `watchdog.restart_xray` | `true` | перезапуск XKeen при пропаже ядра на 3 минуты |
| `telegram.*` | — | `token`, `chat_id`, `expire_days` (3), `traffic_pct` (90), `on_switch`, `on_update` |
| `update_repo` | `furriest/xsub` | источник обновлений |
| `geo.files` | itdoginfo | какие geo-файлы качать в `xray.assetdir` |

Подписки, группы, резервы и списки — файлы рядом с `config.json` (`subscriptions.json`, `groups.json`, `fallbacks.json`, `vpn.txt`, `direct.txt`, `group-*.txt`). Выгружаются и загружаются кнопками «Резервная копия». Ссылки подписок — секреты: права `0600`, в журнал не пишутся.

На накопитель пишется только при изменениях: новая версия подписки, правка списков, geo-файлы, смена конфига Xray. Журнал (`/tmp` по умолчанию) ротируется по `log_max_kb` (текущий + `.old`); последние 80 строк — на странице.

## Безопасность

- Пароль, по умолчанию только домашняя сеть; после 10 неверных паролей адрес блокируется на 10 минут.
- Изменения — только запросами с особым заголовком (чужой сайт не подделает).
- HTTP без шифрования: не выставляйте порт 8099 наружу.
- Панель самовосстановления вернёт конфиги, если их подменит обновление XKeen.

## Ограничения

Пропускаются с предупреждением (нет в Xray): TUIC, Hysteria v1, AnyTLS, NaiveProxy, ShadowsocksR, SSH, Mieru; Shadowsocks с плагинами; VMess с `alterId > 0`; транспорты h2 и QUIC; цепочки `dialerProxy` в JSON-подписках.

- Отключение проверки сертификата (`allowInsecure`) новые Xray не умеют: такие узлы добавляются с обычной проверкой — работают при настоящем сертификате или `pinSHA256`/`pcs` в ссылке.
- Ядро, не принявшее узла: xsub пробует упрощённый вариант (Xray до 26.10 — без перебора портов Hysteria2, старый формат mKCP); иначе отбрасывает только этот узел с причиной на странице.
- WireGuard — в пользовательском режиме (`noKernelTun`), без интерфейса в системе.
- Только ядро Xray; для mihomo есть свои механизмы подписок.

## Сборка и релиз

```sh
go vet ./... && go test -race ./...
scripts/build.sh                 # версия из git describe → dist/
VERSION=1.2.3 scripts/build.sh   # или явно
```

YAML-библиотека в `third_party/` (go-yaml v3.0.1, MIT/Apache-2.0), зависимостей из сети нет. Релиз собирает GitHub Actions по тегу `v*`: пакеты в релизе, opkg-репозиторий на GitHub Pages, образ — в ghcr.

Интерфейс страницы — RU/EN; сообщения xsub (журнал, история, уведомления) — на русском.
