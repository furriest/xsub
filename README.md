# xsub

[English](README.en.md) · Новости: [t.me/xsuby](https://t.me/xsuby) · Чат: [t.me/xsuby_chat](https://t.me/xsuby_chat)

Подписки, списки доменов и сторож узлов для **XKeen + Xray** на роутерах Keenetic / Netcraze.

XKeen перехватывает трафик и запускает Xray. xsub отвечает за содержимое:

- **Подписки.** Понимает почти всё, что умеет ядро Xray:
  - ссылки `vless://`, `vmess://`, `trojan://`, `ss://`, `hysteria2://` (`hy2://`), `wireguard://` (`wg://`), `socks://`, `http(s)://` — списком или в base64;
  - подписки в формате **Clash / mihomo YAML**, **sing-box JSON** и **JSON Xray** (полные конфиги, как отдают Remnawave/Marzban для Happ и v2rayN);
  - транспорты TCP (в том числе с HTTP-заголовком), WebSocket, gRPC, HTTPUpgrade, XHTTP, mKCP; защита TLS и Reality; у Hysteria2 — обфускация salamander, привязка к сертификату и перебор портов.

  Узлы фильтруются по имени, информационные строки панелей («Осталось 10 ГБ» и т. п.) пропускаются. Если панель отдаёт трафик и срок действия, они видны на странице. Подписок может быть несколько.
- **Балансировщик.** Из узлов собирается `07_xsub.json`: outbounds, observatory и балансировщик `leastPing`.
- **Сторож.** Раз в минуту проверяет активный узел **реальной загрузкой** (по умолчанию 32 КБ — больше порога известной блокировки в 16–20 КБ; размер меняется в настройках). Это ловит блокировки, при которых короткие проверки вроде `generate_204` проходят, а настоящий трафик обрывается. Можно добавить свои адреса, которые тоже должны открываться через узел (например, нужный заблокированный сайт). Переключение идёт через API Xray, без перезапуска ядра.
- **Надёжность узлов.** Каждый запасной узел проверяется загрузкой в фоне раз в 30 минут (настраивается), проверки распределяются равномерно. У каждого узла копится история за сутки, и при сбое первыми выбираются проверенные надёжные узлы, а не просто самые быстрые по пингу.
- **Переход на быстрый узел.** Если запасной узел прошёл проверку, надёжен не хуже текущего и быстрее его больше чем на 200 мс (настраивается, 0 — выключить), сторож переключится на него, не дожидаясь отказа. Задержка измеряется при каждой проверке узла.
- **Резервные узлы.** Свои серверы на случай, когда не работает ни один узел подписок: добавляются ссылкой (`vless://`, `socks://`, `http://` и любые другие, что понимает xsub) или переносятся одной кнопкой из конфигов XKeen (например, `04_outbounds.json`). Сторож проверяет их так же, как обычные узлы, включает резерв при отказе всей подписки и каждые 10 минут пробует вернуться обратно.
- **Резерв через интерфейс роутера.** Кнопка «+ Интерфейс роутера» на вкладке «Подписки» → «Резервные узлы»: трафик уходит через туннель, поднятый самой Keenetic OS (`nwg0`, `ovpn_br0` и т. п.), минуя Xray. Это нужно там, где роутер справляется лучше ядра — например, WireGuard с обфускацией. Имя интерфейса выбирается из списка; xsub предупредит, если такого интерфейса сейчас нет. Внутри это outbound `freedom` с привязкой `sockopt.interface`, и сторож следит за ним наравне с остальными резервами.
- **Группы.** Свой список через свою часть узлов: например, «YouTube через Нидерланды» или «ChatGPT только через США». У каждой группы свой балансировщик и свой сторож.
- **Списки «Через VPN» и «Напрямую»** редактируются на странице, туда же можно подключить внешние списки по ссылке (обновляются раз в сутки). Перед применением всё проверяется через `xray -test` на копии конфигов, при ошибке ничего не меняется.
- **«Куда пойдёт этот сайт?»** — вводите домен, ссылку или IP и видите, каким правилом и через какой узел пойдёт трафик (понимает и категории из `.dat`-файлов).
- **Самовосстановление.** Если `05_routing.json` или `07_xsub.json` кто-то заменил (обновление XKeen, другая панель), xsub вернёт их. Если ядро Xray пропало на 3 минуты, xsub перезапустит XKeen (но не трогает его, если вы переключились на mihomo).
- **Уведомления в Telegram:** переключение узла, отказ всех узлов и восстановление, скорый конец подписки или трафика, самовосстановление, новая версия xsub. Если Telegram заблокирован, сообщения уходят через VPN. Каждое сообщение начинается с имени роутера (`hostname`), чтобы различать несколько устройств в одном чате — если это имя не стоит показывать, переименуйте роутер.
- **История** переключений и полоска доступности за сутки по каждому узлу и группе.
- **Настройки на странице**, резервная копия всех настроек одним файлом и восстановление из неё, обновление xsub кнопкой, русский и английский интерфейс.
- **Geo-файлы.** Раз в сутки обновляет [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains) (`geosite_itdog.dat`): категории `russia-inside`, `youtube`, `telegram` и другие.

Один статический бинарник без зависимостей (Python не нужен). Веб-страница встроена в него.

## Требования

- Keenetic / Netcraze с Entware («Поддержка открытых пакетов»);
- [XKeen](https://github.com/jameszeroX/XKeen) с ядром **Xray** (`xkeen -xray`);
- архитектура aarch64, mipsel, mips или armv7;
- **не меньше 100 МБ свободного места** под Entware — на практике это означает USB-накопитель.

### Сколько нужно места

Основное место занимает не xsub, а само ядро Xray. Размеры в распакованном виде, Xray v26.10.21:

| Что | Место |
| --- | --- |
| Бинарник Xray, mips/mipsel | 32,7 МБ |
| Бинарник Xray, aarch64 / armv7 | ~31 МБ |
| `geoip.dat` + `geosite.dat` | 6 МБ |
| xsub | 7,9 МБ |
| XKeen со скриптами и зависимостями (iptables, ipset, curl, ca-bundle, coreutils) | 3–5 МБ |
| **Итого** | **≈ 50 МБ** |

Сверх этого нужен запас: opkg распаковывает пакеты во временную папку, geo-файлы обновляются
через копию рядом, а журнал и кэш подписок тоже где-то лежат. Отсюда рекомендация про 100 МБ.

Оперативная память тоже расходуется: geo-базы ядро держит в памяти, и чем больше подключено
категорий и узлов, тем их там больше. Порога по моделям здесь нет — он слишком зависит от
размера списков, — но на роутерах с минимальным объёмом памяти запас будет небольшим.

**Встроенной памяти Keenetic не хватит.** У моделей со встроенным хранилищем под OPKG это
обычно раздел на 55 МБ, из которых часть уже занята — один бинарник Xray туда не помещается.
Нужен USB-накопитель: подойдёт любая флешка, Entware переносится на неё штатными средствами
Keenetic. Если свободного USB-порта нет — например, единственный занят модемом, — поставить
XKeen с Xray на такой роутер не получится: это ограничение размера ядра Xray, а не xsub.

### Чего ждать от процессора

Xray шифрует трафик на процессоре роутера, аппаратного ускорения для VLESS/Reality нет.
Потолок скорости задаёт именно он, а не тариф провайдера:

- **mips / mipsel** — самый медленный вариант: ядро справляется, но скорость через VPN
  будет заметно ниже скорости канала.
- **armv7** — середина.
- **aarch64** — самый быстрый вариант из доступных.

Какая архитектура у вашего роутера:

```sh
uname -m                  # aarch64, armv7l, mips…
opkg print-architecture   # у MIPS различает порядок байт: mipsel или mips
```

Если скорость важна, померяйте её сразу после установки, выбрав узел вручную на вкладке
«Узлы». Там же видна задержка до каждого узла — она показывает качество маршрута, но
не пропускную способность: упереться можно и в процессор при хорошей задержке.

Сторож добавляет немного трафика подписки: каждая проверка узла — это загрузка 32 КБ
(размер меняется в настройках). Тридцать узлов при проверке раз в 30 минут — около 45 МБ
в сутки.

## Установка

По SSH на роутере (в Entware):

```sh
curl -fsSL https://raw.githubusercontent.com/furriest/xsub/main/install.sh | sh
```

Установщик сам определит архитектуру, проверит, хватает ли свободного места, поставит пакет, создаст конфиг и покажет адрес веб-страницы, логин и пароль. Откройте `http://<IP-роутера>:8099/` и добавьте ссылку на подписку.

Если XKeen ещё не установлен, установщик предложит поставить его (выберите в нём ядро Xray); если у XKeen нет ядра Xray или он работает на mihomo — предложит `xkeen -ux` / `xkeen -xray`. Без терминала он ничего не ставит без спроса; `XSUB_YES=1` — ставить всё без вопросов.

Пока подписка не добавлена, xsub не трогает конфиги Xray.

### Что настраивать вне xsub

В конфигах Xray — ничего: после установки XKeen (ядро Xray) и xsub всё настраивается на веб-странице. `04_outbounds.json` из XKeen можно оставить пустым, `05_routing.json` xsub пишет сам. Вкладка «Настройки» → «Окружение» показывает, всё ли на месте (XKeen, ядро, автозапуск, входы и sniffing), и подсказывает команду, если нет; проблемы видны и на «Обзоре».

Что остаётся на стороне Keenetic и XKeen (по желанию):

- **Шифрованный DNS** (DoT/DoH) в веб-интерфейсе роутера — XKeen рекомендует его, чтобы провайдер не подменял ответы.
- **Политика `xkeen`** в «Приоритетах подключений», если через VPN должны ходить не все устройства. Без неё XKeen проксирует всех клиентов роутера.
- **IPv6.** Если провайдер выдаёт IPv6, часть трафика может пойти мимо прокси; XKeen умеет отключать его (`xkeen -ipv6`).
- **Исключение российских IP** (вопрос при установке XKeen): такие адреса не попадают в Xray, даже если сайт в списке «Через VPN». Это GeoIPSET самого XKeen: управляется командами `xkeen -gips` (включить) и `xkeen -dgips` (выключить). Обе спрашивают подтверждение в терминале, поэтому из xsub не вызываются.

Обновление — та же команда. Если хотите обновляться через `opkg upgrade`, подключите репозиторий:

```sh
curl -fsSL https://raw.githubusercontent.com/furriest/xsub/main/install.sh | XSUB_FEED=1 sh
```

Пакет можно поставить и вручную, но архитектуру нужно взять свою: все пакеты объявлены как `Architecture: all`, поэтому `opkg` не помешает поставить чужую сборку — файл встанет, а запускаться не будет (установка в этом случае сразу об этом скажет).

```sh
case "$(uname -m)" in
  aarch64|arm64) A=aarch64 ;;
  armv*)         A=armv7 ;;
  mips*)         opkg print-architecture | grep -q mipsel && A=mipsel || A=mips ;;
esac
opkg install "https://github.com/furriest/xsub/releases/latest/download/xsub_$A.ipk"
```

Кнопка «Обновить» в настройках xsub скачивает пакет сама — **через VPN, если GitHub недоступен напрямую**, — сверяет контрольную сумму из `SHA256SUMS` и отдаёт файл `opkg install`. Репозиторий opkg для этого не нужен: он остаётся только для ручного `opkg upgrade`, который про VPN не знает и на заблокированном канале может не достучаться до GitHub. Ход обновления виден в настройках и в `/tmp/xsub-update.log`.

## Что меняется в конфигах Xray

xsub пишет два файла в папку конфигов XKeen (`/opt/etc/xray/configs`):

| Файл | Содержимое |
|---|---|
| `05_routing.json` | правила из списков, правило для входов XKeen `force-proxy-*`, балансировщик |
| `07_xsub.json` | узлы подписок, observatory, API (`127.0.0.1:10085`), локальные входы для проверок (`127.0.0.1:10990–10998` для основной цели и групп, `11000+` для узлов) |

`05_routing.json` полностью принадлежит xsub. Свои правила переносите в списки на странице, а не правьте файл: правки затрутся при следующем применении.

Перед первой записью исходные файлы сохраняются в `/opt/etc/xsub/backup/original/`. Вернуть всё как было:

```sh
/opt/etc/init.d/S99xsub stop
xsub -restore
```

`opkg remove xsub` делает это сам.

xsub подстраивается под существующие конфиги:
- sockopt (метку `mark`) узлы берут у `template_tag` или у первого outbound, где он задан;
- для прямого трафика используется outbound `direct` или первый `freedom`. Если их нет, xsub добавит свой;
- если в ваших файлах уже есть секции `api` или `observatory` либо секция `routing` в файле, который читается после `05_routing.json`, xsub не применит конфиг и объяснит, что поправить.

## Списки

Одна запись на строку, комментарии через `#`:

```
example.com                      # домен со всеми поддоменами
=example.com                     # только этот домен
ext:geosite_itdog.dat:youtube    # категория из файла в папке geo-файлов
geosite:telegram                 # категория из geosite.dat
1.2.3.0/24                       # IP или подсеть
regexp:^ads\.                    # регулярное выражение
```

Порядок правил: «Напрямую», затем группы (в порядке на странице), затем «Через VPN». Всё, что не попало ни в один список, идёт напрямую.

**Внешние списки.** Строка со ссылкой `https://…` подключает список из интернета: по одному домену, IP или подсети в строке (понимает и формат dnsmasq `server=/домен/…`). Списки скачиваются при сохранении и обновляются раз в сутки вместе с geo-файлами; на накопитель пишутся только при изменениях.

**Группы** настраиваются во вкладке «Списки и группы»: название и фильтр узлов (регулярное выражение по имени, например `(?i)нидерланд|NL`). У каждой группы появляется свой список. Если подходящих узлов нет, трафик группы идёт основной целью.

Российские подсети XKeen может исключать из проксирования ещё до Xray (`xkeen -gips`).

## Настройки

Основное меняется на странице, во вкладке «Настройки» — это сохраняется в `/opt/etc/xsub/settings.json` поверх `config.json`, и xsub перезапускается сам. Остальное — в `/opt/etc/xsub/config.json` (после правки: `/opt/etc/init.d/S99xsub restart`):

| Параметр | По умолчанию | |
|---|---|---|
| `listen` | `0.0.0.0:8099` | адрес веб-страницы |
| `log_file`, `log_max_kb` | `/tmp/xsub.log`, `256` | журнал, см. ниже |
| `user`, `password` | `admin`, случайный | вход на страницу |
| `sub_interval_hours` | `6` | как часто обновлять подписки (после неудачи — через 10 минут) |
| `user_agent` | `v2rayN/7.0` | панели отдают разный формат в зависимости от клиента; у каждой подписки можно задать свой |
| `max_nodes` | `60` | максимум узлов из одной подписки |
| `xray.fallback_tag` | — | устарело: outbound из конфигов XKeen на случай отказа всех узлов. Используется, только если в xsub нет резервных узлов; лучше перенести его на вкладке «Подписки» → «Резервные узлы» |
| `xray.template_tag` | — | у какого outbound брать sockopt |
| `xray.restart_cmd` | `xkeen -restart` | |
| `xray.manage_api` | `true` | `false` — если API Xray уже настроен у вас (нужен `RoutingService` на `xray.api_listen`) |
| `watchdog.interval_sec` | `60` | |
| `watchdog.fails_to_switch` | `2` | сколько неудач подряд до переключения |
| `watchdog.test_bytes` | `32768` | сколько должно скачаться через узел, чтобы он считался рабочим (8–1024 КБ, меняется на странице) |
| `watchdog.test_url` | Cloudflare | что качать для проверки; `{bytes}` заменяется на `test_bytes` |
| `watchdog.check_urls` | — | дополнительные адреса, которые должны открываться через узел |
| `watchdog.latency_url` | `gstatic.com/generate_204` | чем меряется задержка при каждой проверке узла; если через узлы он не открывается, в таблице будет прочерк — поменяйте адрес |
| `watchdog.switch_faster_ms` | `200` | перейти на запасной узел, если он прошёл проверку, надёжен не хуже текущего и быстрее его на столько миллисекунд (0 — не переходить ради скорости; 50–10000, меняется на странице). Работает только при включённой фоновой проверке и не чаще раза за её цикл |
| `watchdog.background_cycle_min` | `30` | каждый запасной узел проверяется загрузкой раз в столько минут, проверки распределяются равномерно (0 — не проверять). Одна проверка — 32 КБ трафика подписки: 30 узлов при 30 минутах ≈ 45 МБ в сутки |
| `watchdog.stats_file` | `/tmp/xsub-stats.json` | куда класть историю проверок, чтобы она пережила перезапуск xsub (сохранение настроек, самообновление). `/tmp` — оперативная память: флеш не изнашивается, перезагрузку роутера история не переживает. `""` — не сохранять |
| `watchdog.restart_delay_sec` | `7` | пауза после обнаружения запущенного ядра, прежде чем закреплять узлы |
| `watchdog.restart_xray` | `true` | перезапускать XKeen, если Xray пропал на 3 минуты |
| `telegram.token`, `chat_id` | — | уведомления; `expire_days` (3), `traffic_pct` (90), `on_switch`, `on_update` |
| `ui_allow_wan` | `false` | пускать на страницу не только из домашней сети |
| `ui_allow_hosts` | — | имена, по которым разрешено открывать страницу, если ваше не из обычных (IP-адрес, `localhost`, `*.lan`, `*.local`, имена роутера). Защита от DNS rebinding: чужой сайт не сможет обратиться к странице под своим именем |
| `update_repo` | `furriest/xsub` | где проверять новые версии |
| `geo.files` | itdoginfo | какие geo-файлы скачивать в `xray.assetdir` |

Подписки хранятся в `/opt/etc/xsub/subscriptions.json`, группы — в `groups.json`, резервные узлы — в `fallbacks.json`, списки — в `vpn.txt`, `direct.txt` и `group-*.txt` рядом. Всё это вместе выгружается и загружается кнопками «Резервная копия» в настройках.

Статистика узлов и история переключений живут в оперативной памяти; статистика ещё и копируется в `watchdog.stats_file`, поэтому переживает перезапуск самого xsub (сохранение настроек, обновление), но не перезагрузку роутера.

## Журнал и износ флеш-памяти

Журнал по умолчанию пишется в `/tmp/xsub.log` — это оперативная память роутера, поэтому ни встроенная флеш-память, ни USB-накопитель не изнашиваются. Файл ограничен `log_max_kb` (256 КБ): при превышении он переименовывается в `xsub.log.old`, а предыдущий `.old` удаляется, так что журнал никогда не занимает больше двух файлов. Последние 80 строк видны на веб-странице (в памяти держатся 300). После перезагрузки роутера журнал начинается заново.

| `log_file` | |
|---|---|
| `/tmp/xsub.log` | по умолчанию, в оперативной памяти |
| `""` | только на веб-странице, без файла |
| `/opt/var/log/xsub.log` | на накопителе: переживает перезагрузку, но пишет на флеш |

На накопитель xsub пишет только при изменениях: новая версия подписки, правка списков, обновлённые geo-файлы, смена конфига Xray.

## Безопасность

- Веб-страница закрыта паролем и по умолчанию открывается только из домашней сети (и для VPN-клиентов Keenetic). После 10 неверных паролей подряд вход с этого адреса закрывается на 10 минут.
- Изменения принимаются только запросами с особым заголовком, поэтому чужой сайт в браузере не сможет их подделать.
- Не открывайте порт 8099 в интернет: соединение идёт по HTTP. Брандмауэр Keenetic по умолчанию входящие из интернета не пропускает.
- Ссылки подписок — секрет. Они хранятся в файлах с правами `0600` и не пишутся в журнал.

## Ограничения

Пропускаются с предупреждением то, чего нет в самом Xray:
- протоколы TUIC, Hysteria (первая версия), AnyTLS, NaiveProxy, ShadowsocksR, SSH, Mieru;
- shadowsocks с плагинами (obfs, v2ray-plugin и т. п.), VMess с `alterId > 0`;
- транспорты HTTP/2 (`h2`) и QUIC — удалены из Xray;
- цепочки прокси (`dialerProxy`) в JSON-подписках.

Особенности:
- **Проверка сертификата.** Новые версии Xray не умеют её отключать (`allowInsecure`/`insecure=1`). Такие узлы добавляются с обычной проверкой — работают, если сертификат настоящий или в ссылке есть `pinSHA256`/`pcs`.
- **Старые версии Xray.** Если установленное ядро не принимает какой-то узел, xsub пробует упрощённый вариант (для Xray до 26.10 — без перебора портов Hysteria2, прежний формат mKCP). Если не получается, отбрасывает только этот узел и пишет причину на странице, а не ломает весь конфиг.
- **WireGuard** работает в пользовательском режиме (`noKernelTun`), без создания интерфейса в системе роутера.
- Работает только с ядром Xray. Для mihomo подписки и `url-test` есть в самом ядре.

## Сборка

Зависимостей из сети нет: библиотека YAML лежит в `third_party/` (go-yaml v3.0.1, MIT/Apache-2.0).

```sh
go vet ./... && go test -race ./...
scripts/build.sh                 # версия берётся из git describe → dist/
VERSION=1.2.3 scripts/build.sh   # или задаётся явно
```

Релиз собирается GitHub Actions по тегу `v*`. Пакеты прикладываются к релизу, репозиторий opkg публикуется на GitHub Pages (в настройках репозитория: Pages → Source: GitHub Actions).
